# Small product decision record

Copy this into an issue or a short document for a significant feature. A few
sentences per answer are enough. Routine fixes do not need a proposal.

- Feature / owner / date / decision (build, experiment, defer, stop):
- What user problem does this solve, and who experiences it?
- How does it connect to NTM? Does an existing feature already solve it?
- What observation or metric would indicate success? When will we check?
- Smallest useful scope; what is deliberately outside it?
- What maintenance work does it create, and who owns that work?
- Data sources, licenses, legal/privacy dependencies and ongoing costs?
- What evidence, dependency or cost should stop or defer this feature?
- Which area improves, and how: Utility, Research/retention, Learn,
  Distribution, Community, Revenue, Connected Experience?
- Reuse existing components/data; rollout, validation and removal plan:

One strong connection is better than checking every area. The purpose is a
clear experiment and ownership, not approval bureaucracy or feature-count growth.
