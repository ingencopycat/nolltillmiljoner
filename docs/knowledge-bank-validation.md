# Knowledge Bank V1 final report

Implemented locally on 2026-09-15. No commit, push or deployment.

1. **Architecture:** one internal editorial catalog; allowlisted public projection; reusable static landing/answer generator; small client-side search/UI; existing premium styling, SEO and relation pipelines. [Authoring/workflow guide](knowledge-bank.md).
2. **Initial count:** 26 editorial seed Q&As covering the requested concepts, including a separate answer about inconsistent EPS figures. They are not labeled as actual user submissions. Each has a direct answer, explanation, original example, caveat and sources.
3. **Categories:** seven manageable groups: Grunder & aktier, Nyckeltal, Värdering, Rapporter, Sparande & skatt, Makro, Risk & portfölj. Lesson links retain Academy's own stable taxonomy.
4. **Search:** question/alias/concept/category matching, Swedish diacritic and case normalization, P/E punctuation handling, combined category filtering, empty state and keyboard-accessible reset. “Vinst per aktie”, “snittavkastning” and “mäklaravgift” resolve the intended topics. Search text is not persisted or included in URLs/analytics.
5. **Connected Experience:** canonical `knowledge-<id>` entities, explicit answer-to-lesson/tool relations and lesson-to-question relations. Destinations include valuation, FX, returns, fees, ISK, Research and the manual thesis workflow. No parallel hardcoded destination registry.
6. **Academy integration:** related lessons show a compact “Vanliga frågor” disclosure; answers offer “Lär dig mer i Academy”. Existing lessons, activities, XP, history and backup behavior remain intact.
7. **SEO:** 27 new indexable pages: landing plus 26 published answers, bringing the sitemap to 85 canonical URLs. Unique title/description/canonical, static original content and internal links. Reviewed-only entries are public but noindex; drafts and needs-update entries are absent from public output. Orphan generated pages block the build until explicitly retired. No rich-result eligibility or ranking guarantee is claimed.
8. **Editorial workflow:** draft → source/arithmetic/substantive review → reviewed → deliberate publication. Known problems move an entry to needs-update. Internal notes and drafts are excluded from the public JS bundle and production staging. Source/projection and state rules have direct tests.
9. **Source/review rules:** primary authorities and first-party definitions, dated source records, synthetic examples and explicit limits. ISK references the existing dated rule registry and calculator; overdue registry review fails generation. Implementation review was performed by Codex, without claiming a separate human review. Owner maintenance remains necessary.
10. **Future AI:** stable IDs and structured public text can support retrieval, grounded fallback and eval fixtures. The documented owner → ChatGPT draft → reviewer workflow is manual. A future moderated submission queue is documented; no live AI, public submissions or paid APIs were introduced.
11. **Files:** new internal catalog, `knowledge-core.js`, generated `knowledge-catalog.js`, `knowledge-ui.js`, `knowledge.css`, builder/source adapter/quality validator, landing plus 26 answer pages, Knowledge Bank tests and documentation. Updated relation/event catalogs, Academy/SEO builders, staging requirements, navigation expectations, browser/quality suites and staging-isolation assertions. Generated existing HTML changes primarily add the navigation item, FAQ links and public relation dependencies.
12. **Tests:** ten new JavaScript Knowledge Bank contracts cover IDs/slugs, states, unpublished exclusion, private-note projection, aliases, metadata, relationships, safe rendering, SEO, ISK dates, independent arithmetic and analytics privacy. Python navigation/staging assertions updated. One new browser flow covers search/filter/links, keyboard, responsive themes and JavaScript-disabled reading.
13. **Browser/screenshots:** fresh Edge/Chromium 153.0.4234.32 contexts; landing, FX and ISK pages at 360/390/430 in light/dark, plus desktop landing/search and source disclosure. Inspected mobile landing, FX answer, desktop search and source/ISK evidence. [Selected screenshots and quality data](qa/knowledge-bank/README.md).
14. **Validation:** full Python suite: 163 run, 162 passed, one optional database test skipped (`PGLITE_MODULE` absent). Full JavaScript suite: 205 passed, including Knowledge Bank, Academy, backup and Connected Experience. All 37 browser tests pass after updating the existing menu-count assertion for the new entry. Accessibility/CSP: 32 views in both themes at 1440/320, including four Knowledge Bank views. SEO/static generation, 85 sitemap URLs, staging/local references, calendar/rules and `git diff --check` pass. Existing partial/future macro-calendar notices remain unrelated. Practical checks do not constitute exhaustive accessibility certification or field performance measurement.
15. **Remaining gaps:** no submission moderation service, live AI, retrieval backend or user-demand/popularity data. Definitions and sources still need periodic editorial maintenance. Search uses matching and aliases rather than language understanding. The index keeps all 26 questions available, so it is intentionally long on a phone; search/category filtering is the fast route. No new account or personalized tax/advice capability is claimed.
16. **Complete:** yes, the requested initial Knowledge Bank V1 is implemented and locally validated. Ready for product review; not deployed. Future questions should be selected from observed reader needs and reviewed individually, not mass-generated.

Local quality measurements used cold localhost contexts without compression/throttling, excluding third-party requests. The four Knowledge Bank views used 12 local requests each, about 360 KB of JavaScript and 157 KB of CSS, including existing shared site assets. This is a reproducible payload baseline, not Core Web Vitals.
